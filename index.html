CHAPTER 1 — HTML: The Skeleton of the Web

Prerequisites: None. This is where you start.
Time: 8–12 hours

🎯 Learning Objectives

By the end of this chapter, you can:

  1. Write a valid, complete HTML5 document from memory.
  2. Choose the correct semantic element for any content type.
  3. Build accessible forms with proper labels and validation.
  4. Explain what head meta tags do and why they matter for SEO/sharing.
  5. Audit a page for basic WCAG 2.2 AA compliance.

📖 Why This Matters

Every website you've ever used — Google, Instagram, your bank — is HTML at its core. Frameworks like React and Next.js generate HTML, but the browser only understands HTML, CSS, and JavaScript. Developers who skip HTML end up building apps that are slow, invisible to search engines, and unusable with screen readers. HTML is not "easy" — it's foundational, and foundations determine how tall the building can go.

🧠 Core Concepts

1.1 Anatomy of an HTML Document

Create a file called index.html, open it in your browser:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, Web.</h1>
  <p>This page is 100% valid HTML5.</p>
</body>
</html>
LineWhat it does
<!DOCTYPE html>Tells the browser: "render in standards mode," not quirks mode
<html lang="en">Root element; lang helps screen readers and SEO
<meta charset="UTF-8">Character encoding — prevents mojibake (broken characters)
viewport metaMakes the page responsive on mobile — never omit this
<title>Browser tab text; primary SEO signal

1.2 Semantic Structure

Semantic HTML means: the tag describes the content. It's not just for readability — it's how assistive tech and search engines understand your page.

<header>
  <nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
  </nav>
</header>

<main>
  <article>
    <h1>Why Semantic HTML Wins</h1>
    <section>
      <h2>The Problem with Divs</h2>
      <p>A div tells nobody anything. A <code>nav</code> tells everyone.</p>
    </section>
    <section>
      <h2>Accessibility Payoff</h2>
      <p>Screen reader users can jump between landmarks instantly.</p>
    </section>
  </article>

  <aside>
    <h2>Related Reading</h2>
    <ul>
      <li><a href="#">WCAG 2.2 Overview</a></li>
    </ul>
  </aside>
</main>

<footer>
  <p>&copy; 2026 My Site</p>
</footer>

Landmark cheat map:

ElementUse for
headerIntroductory content, site banner
navPrimary navigation links only
mainThe one unique thing this page is about (one per page!)
articleSelf-contained content (blog post, news item, card)
sectionThematic grouping with a heading
asideSidebar, tangential content
figure + figcaptionImages with captions
⚠️ Warning: Don't choose tags based on how they look. h1 isn't "big text" — it's "top-level heading." Style with CSS, structure with HTML.

1.3 Text, Links, and Media

<!-- Headings: exactly one h1 per page; never skip levels -->
<h1>Page Title</h1>
<h2>Section</h2>
<h3>Subsection</h3>

<!-- Links: descriptive text, not "click here" -->
<a href="https://developer.mozilla.org" target="_blank" rel="noopener">
  Read the MDN HTML reference
</a>

<!-- Images: alt text is required unless purely decorative -->
<img src="team-photo.jpg" alt="The five-person engineering team at a whiteboard" />

<!-- Decorative image: empty alt so screen readers skip it -->
<img src="divider-wave.svg" alt="" role="presentation" />

<video controls poster="preview.jpg">
  <source src="demo.mp4" type="video/mp4" />
  Your browser does not support embedded video.
</video>

1.4 Forms — Where HTML Earns Its Keep

<form action="/subscribe" method="POST">
  <label for="email">Email address</label>
  <input
    type="email"
    id="email"
    name="email"
    required
    autocomplete="email"
    placeholder="you@example.com"
  />

  <label for="plan">Choose a plan</label>
  <select id="plan" name="plan" required>
    <option value="">— Select —</option>
    <option value="free">Free</option>
    <option value="pro">Pro</option>
  </select>

  <fieldset>
    <legend>Notifications</legend>
    <label><input type="checkbox" name="newsletter" /> Weekly newsletter</label>
    <label><input type="checkbox" name="product" /> Product updates</label>
  </fieldset>

  <button type="submit">Subscribe</button>
</form>

Form rules worth memorizing:

  • Every input gets a <label for="..."> matched by id. Never use placeholder as a label.
  • name is what gets sent to the server; id is for labels/JS; value is the data.
  • Native validation (required, type="email", minlength, pattern) works even before JavaScript exists.
  • fieldset + legend groups related controls for screen readers.
💡 Tip: Built-in input types — email, url, tel, number, date, range, color — give you free mobile keyboards and validation. Use them.

1.5 Accessibility & Meta Tags (WCAG Starts Here)

WCAG 2.2 AA is the industry bar. HTML covers most of it:

<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <meta name="description" content="Learn full-stack web development from zero to deployment." />

  <!-- Social sharing (Open Graph) -->
  <meta property="og:title" content="The Modern Web Developer" />
  <meta property="og:description" content="A structured path to job-ready full-stack skills." />
  <meta property="og:image" content="https://example.com/cover.png" />

  <!-- Accessibility & theme -->
  <meta name="theme-color" content="#0f172a" />
</head>

The HTML accessibility checklist:

  • ☐ Exactly one h1; headings don't skip levels
  • ☐ All images have appropriate alt (or empty alt="" if decorative)
  • ☐ All form inputs labeled
  • ☐ Landmarks used (header, nav, main, footer)
  • ☐ Sufficient color contrast (covered in Ch. 2)

🔍 Annotated Code Walkthrough: A Complete Landing Page

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <meta name="description" content="TaskFlow — the simple project board for small teams." />
    <title>TaskFlow — Project boards for small teams</title>
  </head>
  <body>
    <header>
      <nav aria-label="Main navigation">
        <a href="/">TaskFlow</a>
        <a href="#features">Features</a>
        <a href="/login">Log in</a>
      </nav>
    </header>

    <main>
      <section id="features">
        <h1>Ship work, not status updates</h1>
        <p>TaskFlow keeps your team focused with one honest board.</p>
        <a href="/signup" role="button">Start free trial</a>
      </section>
    </main>
  </body>
</html>
  • aria-label="Main navigation" — if you have multiple navs (header + footer), label each so screen reader users know which is which.
  • The CTA is a plain a styled as a button. Rule: links navigate, buttons act. It's a navigation to /signup, so a is correct.

MistakeFix

Missing viewport metaPage renders zoomed-out on mobile
img without altScreen readers read the filename aloud. Rude.
Nesting interactive elements (a in a, button in button)Invalid HTML — browsers do unpredictable repairs

CHAPTER 2 — CSS: Styling with Intent

Prerequisites: Chapter 1
Time: 12–18 hours

🎯 Learning Objectives

  1. Explain the cascade and predict which rule wins.
  2. Use the box model, flexbox, and grid to lay out any design.
  3. Build responsive layouts with media queries and fluid units.
  4. Write maintainable CSS with custom properties and sensible naming.
  5. Create animations and transitions that respect prefers-reduced-motion.

📖 Why This Matters

CSS is where users judge your work. Research consistently shows users form aesthetic judgments in about 50 milliseconds. But CSS isn't just paint — it's the layout engine, the responsive strategy, and half of accessibility (contrast, focus states, zoom support). Tailwind (Ch. 3) and component styling in React all compile down to CSS. Understand the fundamentals, and no design will intimidate you.

🧠 Core Concepts

2.1 How CSS Works: Cascade, Specificity, Inheritance

/* A rule = selector + declaration block */
p {
  color: #334155;        /* declaration: property : value */
  font-size: 1.125rem;
}

Three ways to attach CSS: (1) inline style="" — avoid; (2) style in head — fine for demos; (3) external stylesheet — always do this in real projects.

Specificity (higher wins):

Selector typeSpecificityExample
Inline style1000style="color:red"
ID100#submit-btn
Class / attribute / pseudo-class10.card, [type="email"], :hover
Element / pseudo-element1p, ::before
/* Who wins on this button? */
button { color: black; }              /* 1    — loses */
.btn   { color: blue; }               /* 10   — loses */
#save  { color: green; }              /* 100  — WINS */
⚠️ Warning: When CSS "doesn't work," 80% of the time it's a specificity battle you didn't know you were fighting. Don't reach for !important — that's surrender, not strategy. Restructure selectors instead.

Inheritance: text properties (color, font-*) inherit from parent; box properties (margin, border) don't. You can force inheritance: box-sizing: inherit;.

The box-sizing reset (put this at the top of every project):

*, *::before, *::after {
  box-sizing: border-box;
  margin: 0;
}

2.2 The Box Model

Every element is a box: content -> padding -> border -> margin.

.card {
  width: 300px;
  padding: 24px;        /* space inside the border */
  border: 2px solid #e2e8f0;
  margin: 16px auto;    /* auto L/R centers a block with a set width */
}

[DIAGRAM: Box model — concentric layers labeled content/padding/border/margin]

💡 Tip: With box-sizing: border-box (the reset above), width: 300px means the whole visible box is 300px including padding and border. Without it, padding gets added on top — the #1 beginner layout bug.

2.3 Flexbox — One Dimension

.navbar {
  display: flex;
  justify-content: space-between;  /* main axis (horizontal by default) */
  align-items: center;             /* cross axis (vertical) */
  gap: 1rem;                       /* modern spacing — no margin hacks */
}

.navbar .spacer { margin-left: auto; } /* push everything after it right */

[DIAGRAM: Flexbox axes — main axis arrow left-to-right, cross axis top-to-bottom]

Properties: on the parent -> display, flex-direction, justify-content, align-items, gap, flex-wrap. On children -> flex: 1, align-self, order, flex-shrink: 0.

.card-row {
  display: flex;
  flex-wrap: wrap;
  gap: 1.5rem;
}
.card-row > * {
  flex: 1 1 250px;   /* grow shrink basis — "be at least 250px, share space" */
}

2.4 Grid — Two Dimensions

.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 1.5rem;
}

That single line gives you a fully responsive card grid with zero media queries. auto-fit collapses empty tracks; minmax(220px, 1fr) means "never smaller than 220px, share the rest equally."

.page-layout {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}
.page-layout > header { grid-area: header; }
/* etc. — explicit areas beat numeric line math for app shells */

[DIAGRAM: Grid areas layout — labeled header/sidebar/main/footer]

2.5 Responsive Design

/* Mobile-first: base styles for small screens, then enhance */
.container {
  padding: 1rem;
  font-size: 1rem;
}

@media (min-width: 768px) {   /* tablet and up */
  .container { padding: 2rem; font-size: 1.125rem; }
}

@media (min-width: 1024px) {  /* desktop and up */
  .container { max-width: 72rem; margin-inline: auto; }
}

Fluid units cheat:

UnitMeaningUse for
remRelative to root font size (16px default)Almost everything
emRelative to the element's font sizeComponent-internal spacing
% / vw / vhContainer / viewport percentageWidths, hero sections
clamp(min, preferred, max)Fluid interpolationTypography: font-size: clamp(1rem, 0.6rem + 2vw, 1.5rem)
💡 Tip: min(), max(), clamp() and container queries have replaced most media queries in modern CSS. clamp() alone handles fluid typography.

2.6 Transitions, Animations, and Custom Properties

:root {
  --color-primary: #4f46e5;
  --radius: 0.5rem;
}

.button {
  background: var(--color-primary);
  border-radius: var(--radius);
  transition: background 150ms ease, transform 150ms ease;
}
.button:hover { background: #4338ca; transform: translateY(-2px); }

@keyframes pulse {
  50% { transform: scale(1.05); }
}
.badge { animation: pulse 2s ease-in-out infinite; }

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;  /* accessibility override */
    transition-duration: 0.01ms !important;
  }
}
⚠️ Warning: Only transform and opacity are cheap to animate. Animating width, height, or top/left triggers layout recalculation and jank.

Accessibility: always check contrast (WCAG AA: 4.5:1 for text, 3:1 for large text). Chrome DevTools color picker shows the ratio. Never remove focus outlines without replacing them: :focus-visible { outline: 2px solid var(--color-primary); }.

🔍 Annotated Code Walkthrough: A Pricing Card

<section class="pricing-card">
  <h2>Pro</h2>
  <p class="price">$12<span>/mo</span></p>
  <ul>...</ul>
  <a class="button" href="/checkout">Choose Pro</a>
</section>
.pricing-card {
  display: flex;              /* stack children vertically */
  flex-direction: column;
  gap: 1rem;
  padding: 2rem;
  border: 1px solid #e2e8f0;
  border-radius: 1rem;
  max-width: 320px;
}

.price span {                /* "12" big, "/mo" small */
  font-size: 0.5em;
  color: #64748b;
}

.button {
  margin-top: auto;           /* pins button to card bottom — flexbox trick */
  text-align: center;
  padding: 0.75rem 1rem;
  background: var(--color-primary);
  color: #fff;
  border-radius: var(--radius);
  text-decoration: none;
  font-weight: 600;
}
  • flex-direction: column turns the main axis vertical, so margin-top: auto pushes the button to the bottom — this makes equal-height cards trivially.
  • font-size: 0.5em is relative to the parent's font size — the elegant way to size a suffix.

⚠️ Common Mistakes & Gotchas

MistakeFix
Forgetting box-sizing: border-boxAdd the reset; always
Centering with margin-top pixel guessesFlexbox: display:flex; justify-content:center; align-items:center on the parent

CHAPTER 3 — Tailwind CSS: Speed Through Utilities

Prerequisites: Chapter 2 (box model, flexbox, responsive units)
Time: 8–12 hours

🎯 Learning Objectives

  1. Explain the utility-first philosophy and when to use component extraction.
  2. Set up Tailwind in a project via the CLI.
  3. Compose layouts, spacing, and typography purely with utilities.
  4. Use responsive, state, and dark-mode variants fluently.
  5. Configure a design system via theme tokens.

📖 Why This Matters

Writing raw CSS is powerful but slow at scale — you invent class names, jump between files, and re-solve the same spacing problems daily. Tailwind compresses that: every project shares one vocabulary (flex, p-4, text-slate-700), designs stay consistent by construction, and you never write a stylesheet from scratch again. Tailwind is now the default styling layer of the React/Next.js ecosystem — you'll meet it again in Chapters 5 and 6.

🧠 Core Concepts

3.1 Setup (2026 CLI — standalone, no framework needed)

# In your project folder
npm install tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i ./src/input.css -o ./dist/output.css --watch
/* src/input.css — the new v4 style: one import line */
@import "tailwindcss";

/* your custom design tokens live here */
@theme {
  --color-brand: #4f46e5;

3.3 Responsive & State Variants

Variants are prefixes, stacked left-to-right, mobile-first:

<button class="bg-indigo-600 px-4 py-2 text-white
               hover:bg-indigo-500              <!-- state -->
               focus-visible:outline-2           <!-- a11y -->
               disabled:opacity-50               <!-- state -->
               md:px-6                           <!-- >=768px -->
               lg:px-8">                         <!-- >=1024px -->
  Continue
</button>

That single element, zero custom CSS, is fully responsive, keyboard-accessible, and handles disabled state. Notice focus-visible — same accessibility discipline as Chapter 2.

3.4 Component Extraction — @apply and the "When"

When a pattern repeats (cards, buttons, nav bars), stop duplicating 8 utilities across 12 files. Extract a component class:

@layer components {
  .btn {
    @apply rounded-lg bg-indigo-600 px-4 py-2 font-semibold text-white
           transition hover:bg-indigo-500 focus-visible:outline-2
           disabled:opacity-50;
  }
  .btn-secondary { @apply btn bg-slate-200 text-slate-900 hover:bg-slate-300; }
}
<button class="btn">Save</button>
<a class="btn btn-secondary" href="/docs">Read docs</a>

Rule of thumb: extract at 3+ usages. A one-off stays inline.

⚠️ Warning: Over-extraction kills Tailwind's advantages (grep-ability, no naming). Under-extraction creates 400-line class attributes. Balance.

3.5 Dark Mode

/* input.css */
@custom-variant dark (&:where(.dark, .dark *));
<html class="dark">
  <body class="bg-white text-slate-900 dark:bg-slate-950 dark:text-slate-100">
    ...
  </body>
</html>

The .dark class on html is toggled by JavaScript (Ch. 4) and persisted — the standard pattern you'll reuse in React (Ch. 5).

3.6 The Design-System Mindset

Tailwind's real gift isn't speed — it's constraints. Spacing, colors, and radii come from a fixed scale, so "looks off by a pixel" bugs disappear. Extend it deliberately, not randomly:

@theme {
  --color-brand: #4f46e5;
  --color-brand-light: #818cf8;
  --font-display: "Inter", sans-serif;
}
<h1 class="font-display text-4xl text-brand">Your brand, systematized</h1>
